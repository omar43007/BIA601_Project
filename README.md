# BIA601_Project
# مشروع BIA601: توزيع المساعدات بمركبة واحدة

هذا المشروع ينفذ ويقارن ثلاث خوارزميات تحسين ذكية على مسألة توزيع مساعدات من مستودع واحد إلى مجموعة نقاط، باستخدام مركبة واحدة. المسألة مكافئة لمسألة البائع المتجول (TSP): تبدأ المركبة من المستودع، تزور كل نقطة مرة واحدة، ثم تعود إلى المستودع، والهدف تقليل طول المسار الكلي.

الخوارزميات المنفذة:

- الخوارزمية الجينية (GA) بتمثيل التبديل وتزاوج OX وطفرة عكس مقطع.
- تحسين سرب الجسيمات (PSO) بتمثيل السرعة كسلسلة تبديلات.
- مستعمرة النمل (ACO) بنظام Ant System مع تعزيز أفضل مسار.
- البرمجة الديناميكية (DP) بخوارزمية Held-Karp كحل دقيق للمقاس الصغير.

## المتطلبات

- Python 3.10 أو أحدث.
- مكتبة Pillow لرسم الأشكال.

التثبيت:

```bash
python -m pip install -r requirements.txt
```

## طريقة التشغيل

من داخل مجلد المشروع:

```bash
python run_all.py
```

يقوم الأمر بتوليد ملفات البيانات إذا لم تكن موجودة، ثم تنفيذ جميع التجارب (3 أحجام × 3 خوارزميات × 10 تشغيلات)، وحفظ النتائج في مجلد `results`، ورسم الأشكال في `results/figures`.

خيارات إضافية:

```bash
python run_all.py --runs 5 --budget 10000
python run_all.py --no-figures
```

- `--runs`: عدد التشغيلات المستقلة لكل خوارزمية على كل حجم، والقيمة الافتراضية 10.
- `--budget`: عدد الحلول المقيمة لكل تشغيل، والقيمة الافتراضية 15000.
- `--no-figures`: تخطي رسم الأشكال عند إعادة التجارب فقط.

## البيانات

كل ملف CSV يحتوي ثلاثة أعمدة: `id` و`x` و`y`. النقطة ذات المعرف 0 هي المستودع، وبقية النقاط هي نقاط التوزيع. الإحداثيات داخل مربع [0,100] × [0,100]، والمسافة بين أي نقطتين هي المسافة الإقليدية.

| الحجم | عدد النقاط | بذرة التوليد | الملف |
|---|---:|---:|---|
| صغير | 10 | 101 | `data/small.csv` |
| متوسط | 20 | 202 | `data/medium.csv` |
| كبير | 40 | 303 | `data/large.csv` |

معيار التوقف لجميع الخوارزميات هو استهلاك ميزانية التقييم، باستثناء DP الذي يتوقف عند اكتمال الجدول.

## النتائج المختصرة

المتوسطات من 10 تشغيلات لكل حالة:

| الحجم | GA | PSO | ACO | المرجع |
|---|---:|---:|---:|---:|
| صغير (10) | 342.70 | 347.46 | 344.93 | 340.75 (DP) |
| متوسط (20) | 393.61 | 554.75 | 367.31 | 367.31 |
| كبير (40) | 750.12 | 1504.17 | 531.71 | 526.30 |

في الحجم الصغير استخدم DP كمرجع دقيق. في الحجمين المتوسط والكبير استخدم أفضل حل وصلت إليه أي خوارزمية كمرجع، وليس الحل الأمثل المثبت.

الخلاصة أن ACO كانت الأفضل في الحجمين المتوسط والكبير مع استقرار عالٍ، بينما كانت GA أسرع وأفضل في الحجم الصغير. PSO كانت الأضعف في هذا التمثيل، لأن تمثيل السرعة كسلسلة تبديلات يفقد البنية الجيدة للمسار عند زيادة الحجم. التفاصيل الكاملة والمناقشة موجودة في التقرير المرافق.

## إعادة الإنتاج

- جميع البذور ثابتة، لذلك تعطي التجارب النتائج نفسها على الجهاز نفسه.
- أزمنة التنفيذ تعتمد على الجهاز، وقد تختلف قليلاً بين تشغيل وآخر.
- لحفظ النتائج الحالية كما هي، لا تحذف مجلد `results` قبل التسليم.
- يمكن إعادة أي تجربة بمفردها من خلال استدعاء الدوال في `src/ga.py` و`src/pso.py` و`src/aco.py` مع تمرير كائن `Instance` والبذرة المطلوبة.
